# 临床数据雷达 · Clinical Data Radar

每天自动追踪**临床研究数据与进展**——是否达到终点、是否终止、关键节点——
打分后挑出 2-3 条，搜一手材料，写成中文分析稿，发布到 GitHub Pages 并推送飞书。

**中国创新药临床 / 全球重大临床** 两个栏目分开选题。

> 姊妹项目：[医药 BD 雷达](https://github.com/liaoguogang-hub/pharma-bd-radar)
> —— 那个做 BD 交易，这个做临床数据。两者架构同源，领域不同。

---

## 它做什么

```
采集临床专业源 → 临床噪声过滤 → 去重 → LLM 五维评分 → 双栏目选题
                                          ↓
                        一手材料补全（ClinicalTrials.gov + 终点判定）
                                          ↓
                              成稿 → 质检 → Pages + 飞书
```

关注的内容：
- 临床试验结果读出（达到 / 未达到主要终点）
- 试验终止 / 暂停 / 失败（**这类媒体不一定报，但很重要**）
- 关键节点（入组完成、期中分析、启动注册试验）
- 监管审批（作为临床进展的结果）

**不关注**：纯 BD 交易（那是 BD 雷达的领域）、人事变动、融资。

---

## 与 BD 雷达的关键差异

| | BD 雷达 | 临床数据雷达 |
|---|---|---|
| 核心对象 | 一次性交易公告 | **有状态的试验** |
| 数据性质 | 非结构化新闻 | **半结构化**（注册库有字段） |
| 关键判据 | 首付金额、首创性 | **终点是否达到、是否终止** |
| 失败的价值 | 低 | **高**（III 期失败是行业级事件） |
| 噪声过滤方向 | 留交易、剔临床 | **留临床、剔交易** |
| 一手材料 | SEC EDGAR | **ClinicalTrials.gov + 期刊** |

## 快速开始

```bash
pip install -r requirements.txt

cd src
python fetch.py 2026-10-11        # 采集
python dedupe.py 2026-10-11       # 去重
export LLM_API_KEY=...            # 评分与成稿需要
python score.py 2026-10-11        # 临床五维评分
python pick.py 2026-10-11         # 双栏目选题
python enrich.py 2026-10-11       # 一手材料 + 终点判定
python compose.py 2026-10-11      # 成稿
python publish.py 2026-10-11      # 建站点 + 飞书
```

冒烟测试不需要 key：

```bash
gh workflow run radar.yml -f skip_llm=true
```

## 评分维度（总分 10）

| 维度 | 满分 | 判据 |
|---|---|---|
| 终点结果 | 3.0 | 达到且显著 / **未达到** / 安全性终止 / 数据积极但未明确 |
| 阶段与规模 | 2.0 | III 期 2.0 / II 期 1.2 / I 期 0.5；样本量加分 |
| 未满足需求 | 1.5 | 无药可治 1.5 / 疗法有限 1.0 / 竞争激烈 0.3 |
| 首创性 | 1.5 | 全球首个机制 1.5 / 国产首个 1.0 / me-too 0.2 |
| 数据成熟度与可信度 | 2.0 | 顶刊 2.0 / 会议 1.5 / 注册库统计量 1.3 / 仅裸数值 0.6 |

**关键立场**：
- **失败和终止加权，不降权**——III 期失败是行业级事件
- **疗效数据 ≠ 达到终点**——"38 例全部应答"是疗效数字，
  "达到主要终点"是统计结论，两者不可等号连接

## 终点判定的来源分级（本项目最重要的设计）

**ClinicalTrials.gov 不给"是否达到终点"的结论，只给数值。**
统计分析（`analyses[]`，含 p 值/CI）实测只有约 **1/3** 的试验有。
所以判定分四档，**每档在文章里的表述方式不同**：

| 依据层级 | 允许的表述 | 禁止的表述 |
|---|---|---|
| `statistical` 注册库 p 值/CI | 「达到主要终点」 | — |
| `registry_status` 注册库状态 | 「试验已终止」 | — |
| `textual` 新闻/公告措辞 | 「据公告，称达到主要终点」 | 不能说成已确证 |
| `numeric` 仅裸数值 | 「注册库显示 X 组为 Y，未提供统计检验」 | **绝不能写「达到终点」** |

## 踩过的坑（都写在代码注释里）

### 1. 误匹配：8 个注册库命中里 4 个是错的

逐层挖出 4 种不同的病因：

| 层 | 病因 | 实例 |
|---|---|---|
| 1 | 英文短语被当药名 | `double-blind` / `parallel-group` / `open-label` |
| 2 | **自我确认** | 垃圾词搜出的试验，自己成了自己的锚，必然过闸门 |
| 3 | 锚收了对照药 | 搜 Retatrutide 命中正确试验，但它干预含 `tirzepatide`，全收进锚后任何 Tirzepatide 试验都能过 |
| 4 | 搜了对照药 | `Iberdomide + Daratumumab` 两个都搜，后者的命中被当锚 → 放行了**不含 iberdomide** 的试验 |

修法：药名后缀白名单 + 锚只取匹配检索词的那一个干预 + **只搜主药名** +
最终闸门（必须对上主药名）+ **去掉对照药兜底**。

**结果：误匹配 0，保守拒绝 3。** 代价是同一药物名字不一致时会误杀
（Kodiak 的 `tabirafusp-ted` 在注册库叫 `KSI-501`）——这是刻意取舍，
**错材料比没有材料严重得多**。

### 2. `\b` 在中文和拉丁字母之间不成立

标题 `恒瑞医药SHR-1819 III期…` 里，"药"和"S"之间**没有**词边界——
Python 的 `\w` 默认包含中日韩字符，两个都是 word char。
结果药物代号整个抽不出来。改用 `(?<![A-Za-z0-9])` 显式断言。

### 3. CT.gov 完全不索引中文公司名

```
query.spons=恒瑞医药 → 0     query.spons=Hengrui → 916
query.spons=百济神州 → 0     query.spons=BeiGene → 189
```

已建 ~50 家公司的中英映射表。**小公司查不到是正常的**——
返回"未找到"比返回错材料好。

### 4. 年份被编造

第一版生成的稿子写「**2025**年10月8日」，当年数据全是 2026 年的。
根因是链路断了：`raw.published` 有值，但 `scored.published` **字段不存在**
（评分回填时漏了），`build_material` 里也**完全没有发布日期**。
模型看不到就自己编了一个。

修了三处：回填 `published` + 素材里显式标注发布日期 +
新增校验（HOOK 年份与源发布日期不符就打回）。

### 5. 生物谷有腾讯 WAF，而且它假装成功

连续抓 6 个专科频道后触发，之后**全站所有路径**都返回同一个 1681 字节
验证码页，**HTTP 状态码仍是 200**。

不显式识别的话，表现是"这个源今天突然没内容了"，会被误诊成选择器坏了。
已加 `looks_blocked()` 检测，现在明确报拦截。
同时降频到 3 个频道 + 同域请求间隔 2 秒。

### 6. 阈值不能在脏数据上标定

BD 雷达的 8.5/7.5 那组阈值，是在"41 笔旧交易被当成新交易"的污染数据上
定出来的。清掉污染后真实分布顶格只有 7.5，导致多数日子产出 0-1 篇。

本项目的阈值（7.5 / 6.0）先给保守初值，**跑够 3 天真实数据后再校准**，
校准时看的是分数分布，不是感觉。

### 7. AI 味词检查过度触发 / 字数下限太紧

有一篇第 3 次尝试已写出 **3797 字（在范围内）**，仅因 3 个 AI 味词被打回，
第 4 次掉到 1621 字，最终成稿失败。另有一篇写到 **2243 字，
离下限 2250 只差 7 个字**被打回。

**为几个词或几个字重写整篇，代价远大于收益。**
已把 AI 味软档降级为提示，字数下限从 2250 放宽到 2100。

## 已知边界

1. **注册库命中的试验未必是新闻讲的那个**。中国试验大量注册在 CDE
   而不是 CT.gov，所以常只能找到同药的其他试验。已在素材里显式警告。
   *根本解法是接 CDE 注册库。*
2. **注册库更新滞后**。公司先发顶线公告，几周后才提交结果模块。
   实测 7 个命中里拿到统计检验的是 **0 个**。
3. **中文医药自媒体主阵地是微信公众号**，基本抓不了。
   可行的替代是有网页镜像的（药时代、医药魔方、摩熵）。
4. **名字映射**：同一药物在新闻与注册库可能用不同名字
   （INN 全称 / 代号 / 商品名），目前靠后缀白名单 + 锚匹配，
   覆盖不全时会保守拒绝。

## 配置

```bash
gh secret set LLM_API_KEY          # 必填
gh secret set FEISHU_WEBHOOK       # 选填，不配则跳过推送
gh secret set FEISHU_SECRET        # 仅当机器人开了签名校验
gh variable set SITE_BASE_URL --body "https://<user>.github.io/<repo>"

gh api -X POST repos/<user>/<repo>/pages -f build_type=workflow
```

支持 MiniMax / DeepSeek / 任意 OpenAI 兼容端点，改 `config/scoring.yaml`
的 `llm.provider` 即可。

Cron 是 UTC：`0 23 * * *` 和 `0 11 * * *` = 北京时间 07:00 和 19:00。
